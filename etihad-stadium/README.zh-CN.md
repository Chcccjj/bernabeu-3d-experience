# 伊蒂哈德 · 建筑档案

2026 扩建版的资料驱动初步模型，使用本地 Three.js 0.180.0。主体以米为单位；当前不属于经测绘认证的全场 1∶1 模型。

## V14 · 五语、入场路线与参观触发进球

- 右上角提供中文 / English / Español / Français / 日本語，覆盖主体验的导航、结构控制、创作工作台、辅助标签和动态比分。选择会写入当前浏览器并保存在链接参数中；切换语言不重置参观时间或比分。研究档案中的原始研究内容保留中文。
- 比赛日适度加强看台环境补光及球场已有泛光灯，保留夜间氛围。相同1280×720比赛机位的草坪像素样本平均亮度约为V13的1.36倍。
- 456名附近访客（窄屏228）分布在东西两侧步道、南侧广场和13处小组，包含散步、等候和聊天。原1296名入场支持者使用从南侧步道到9个入口的有限路线，到门内后结束，不在近处循环重生；已经入场的角色不回到队尾。
- 比分从“曼城0:0曼联”开始。仅在比赛日且相机处于球场内部时累计停留；场外、页面隐藏和暂停时不增加。累计15秒后仅曼城进一次球，比分保持“曼城1:0曼联”，屏幕记分牌同步。重新开启比赛日会开始新一轮参观演示。

验证：`check-visit-i18n.mjs` 覆盖场外不触发、14.99秒/15秒边界、暂停、复位、仅进一球、144人×2000时刻的单调路线及5语字典；`check-matchday-life.mjs` 继续验证停车/行人包络与球员范围。网页实际验收了5语选择、日语刷新记忆、手机导航、场外0:0及场内1:0，语言变化保留1:0。

## V13 · 比赛日与日常停车

点击“建筑控制 → 比赛日”，可切换左下角的“球场比赛 / 入场人流 / 停车场”：

- 9 个现有模型入口、最多 1296 名入场球迷，排队向入口移动；路线是展示模拟，不是现实疏散/售票流量模型。
- 看台 53,433 名实例观众通过 GPU 顶点动画错峰上下起伏，进球时动作加强。
- 曼城蓝衣、曼联红衣各 11 人，加 1 名裁判；跑动肢体、传球、推进、射门、进球、比分与重新开球循环。它是程序化德比演示，不连接真实赛事数据。
- 东侧已有停车场在日间、夜间、比赛日都运行。6 辆活动车辆进入、入位、倒车出位和驶离；司机下车步行至入口、停留后返回。道闸随车辆抬起，场内车辆依次让行，并与原道路交通共享进出让行区域。
- 原停车区的静态方盒车辆换成与动态车辆一致的造型。场内观察镜头隐藏被建筑遮挡的场外人群，保留逻辑时钟与日常停车流程。

验证：`scripts/check-matchday-life.mjs` 连续模拟 360 秒，包含入位/离场、静态车位包络与司机穿行检查、球员间距与草坪/球门范围、暂停及模式切换。`validation/v13-architecture-preservation.json` 确认 17 组非场地建筑几何保持 V12 原样；GLB 文件哈希与重新导入检查继续通过。本机比赛镜头短时样本为 57→60 FPS，不代表所有硬件、角度的帧率保证。

## V12 · 城市与创作工作台

以 [Chcccjj 的伯纳乌项目](https://github.com/Chcccjj/bernabeu-3d-experience) 和[线上模板](https://bernabeu-architecture-studio.justllama33.chatgpt.site/)为功能参照，在伊蒂哈德既有模型上实现：

- 拍照：6 个机位、4 种比例、1024/2048/3840 长边、PNG/JPEG、曝光/FOV、三分构图线。
- 录像：城市环绕、电影巡游、固定屋盖拆解；横/竖/方形，1280/1920 长边，浏览器支持的 MP4 或 WebM，合成环境音、进度、预览、下载。
- 探索：按方向/层级/排号进入模型席位，也可直接点击实际座椅；建筑热点、步行路线、城市环绕、自由移动、原有剖切与楼层工具。
- 分享：机位/光照/层显隐/剖切/拆解状态链接；最多 8 个本地收藏机位。
- 曼彻斯特城市背景：红砖街区、工业建筑、远处西侧天际线、道路车辆与暖色窗灯。近校园保持开阔，场景向远处延伸。可关闭背景。

此次用户新增城市背景要求，取代旧版“完全不扩展背景”的范围。原球场及校园母模型仍保持原米制尺寸，18 组建筑几何缓冲/实例/世界变换与 V11.5 逐组哈希相同；城市仅为网页背景，不写入建筑 GLB。远处街区为 C 类氛围示意，不是逐栋测绘的曼彻斯特，选座不是官方票号。固定屋盖采用拆解展示，活动覆盖为临时保护层，保留伊蒂哈德身份。

验收：`validation/v12-studio-check.json`、`validation/v12-architecture-preservation.json`、`validation/v12-browser-acceptance.json`；预览 `previews/v12-city-day.png`、`previews/v12-city-night.png`、`previews/v12-mobile-tools.png`。

## 建筑母模型版

- 105 × 68 米草坪与约 6 米下沉标高。
- 62,368 个示意座席；此数为当前生成模型的几何数量，不是现实座位编号或官方容量统计。
- 2026 北看台的 59 排连续上层、桅杆拉索、屋面采光带、8 座螺旋交通塔。
- 北侧双翼建筑、酒店折板幕墙、蓝色端墙、砖裙房、中央雨棚与桥接结构。
- 18 组独立显隐/聚焦、连续拆解、纵剖、六个建筑视角、昼夜、移动行人车辆、视图导出。
- 按原工程拓扑建立四股独立张力环索；主梁与檩条归入独立钢结构系统，隐藏屋面后可检查框架。12 根雪茄形桅杆分组，其中 8 根落在交通塔顶、4 根落地，轴向套箍与支承节点可查看。杆径、塔顶标高与 2026 保留状态仍待校准。
- 共享座席留空与台阶轴线，座椅靠背朝向场外，通道投影侵占和座椅朝向通过实际几何检查；此排布仍需真实座席图校准。
- 每席独立实例化支架、径向箱梁、UB 檩条、V 支撑、扇形拉索、灯具支架与屋面排水检修构件。
- 新北看台两座 A 形支撑的圆环构件、顶板和屋顶边缘护栏，按施工/开放实景拟合；具体断面、连接方式及护栏定位仍待竣工资料校准。
- 北看台八个批准图纸 FFL 标高控制框、单层选择及独立 GLB。控制框不代表楼板边界；主体看台/屋顶仍待整体校准。
- 三层可独立选择的环廊楼板与柱网，为内饰深化保留可编辑结构。
- 建模几何约为首版的 2.33 倍，原预览地块仍为 470 × 500 米；该条记录描述原母模型地块；V12 另有可关闭的远景背景。
- GLB 母模型与楼层壳体，单位为米、保留分组，可通过页面下载 ZIP。
- 22 张去重参考画面及可追溯来源；完整资料保存在上一级 research/。

## 证据与限制

本次仓库整合更新了北看台检查的座椅分区选择器，通道带探测报出 `Egress band crosses aisle 0`。模型保持原样，该项作为待复核问题保留，详见[整合记录](../docs/ETIHAD-INTEGRATION.md)，不作为本轮新的建筑净空验收。

A：草坪 105 × 68 米及下挖约 6 米有官方/工程依据。
B：原结构12桅杆、8坡道塔、76前拉索与新北看台59排有来源；2026改建如何保留每个旧构件仍需最新版图纸核对。
C：外轮廓、层高、酒店及翼楼尺寸、座席布置、灯位、道路及停车场按公开影像初步拟合，尚未全部量测校准。三层环廊暂定标高为 0.82 / 9 / 20.1 米；原工程有三层环廊与约 7.6 米柱网的依据，这不等于这些标高已经证实。

原2003结构、2015扩建和2026北侧工程不可混为同一竣工状态。全场实测1∶1目标仍需2026竣工BIM/标注图纸。当前不含后台室内、博物馆展陈、真实地下机电或可开闭屋顶；拆解是展示分层示意。

## 构建与检查

从仓库根目录执行 `npm ci --ignore-scripts` 后，可用 `npm run check:companion` 检查源码语法、第三方哈希、两份 HTML 的模块图和模型 ZIP，并在临时副本中执行 9 个当前源码检查。需要 Python 3，无额外 Python 依赖。根目录的 `npm run check` 同时覆盖伯纳乌与本项目。历史提交对比脚本保留作来源记录，不在当前仓库假装重跑。

```
python3 scripts/build-research.py
python3 scripts/export-html.py --output dist/index.html
cp research.html dist/research.html
cp -R assets/. dist/assets/
node --experimental-loader ./scripts/local-loader.mjs ./scripts/check-model.mjs
node --experimental-loader ./scripts/local-loader.mjs ./scripts/check-seats.mjs
```

几何改变后，先执行 `node --experimental-loader ./scripts/local-loader.mjs ./scripts/export-master.mjs`，再更新 `models/Etihad-2026-editable-models.zip` 并复制 ZIP 与清单到 `dist/models/`。原始 GLB 保留本地、不加入部署；网页提供压缩包下载。

`MODEL-CHECK.json` 记录米制尺寸、实例数量、屋面法线、18 组结构、场地面积与 GLB 重新导入检查。浏览器检查包括日/夜、屋架、场内、楼层选择、展开/复原、纵剖及窄屏布局。硬件性能只适用于本次浏览器，不能推断所有手机。

## 结构

`bowl-sections.js`：统一看台、座椅、台阶和扶手的断面参数，当前行高/行深仍为 C 类拟合；`scene.js`：米制建筑与导航；`stadium-detail.js`：结构与可编辑楼板；`building-spec.js`：确证参数、拟合参数及来源；`project.config.js`：相机与质量；`src/`：沿用并适配 Little Worlds 的运行、材质、光照、演员及模拟系统。

导出文件及导入方式见 `models/README.md`，第三方模块来源见 `validation/vendor-provenance.json`。持续工作断点在上一级 `WORK-CONTINUATION.md`。

默认主场取景倍率为2（相较前版的1），初次打开、复位及收拢均使用两倍倍率；“整场总览”和其他专业视角保留各自取景。此为镜头倍率，米制实体和GLB尺寸不变。

材质深化见 sources.md：自然铝屋面折缝、透光聚碳酸酯、玻璃反射及克制的日夜光影。新增正投影总平，可从观察预设进入；?render=plan&time=day 为纯净成图页，其他支持hero/north/roof。模型实体尺度与场地范围保持不变。
