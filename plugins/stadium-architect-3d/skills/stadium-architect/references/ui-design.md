# StadiumArchitect UI Design Contract · Quiet, Refined, Architectural

本文件定义所有生成网页的**默认且强制**视觉质量。目标是让用户看见建筑本身，而不是开发者炫技界面。V1 和 V2 必须使用同一设计语言；V2 仅升级细节和体验。参考插件自带的 `assets/starter-v1/src/style.css` 与 `main.js` 中的紧凑浮动 Dock，不要复制用户截图中的 S/A 大标、版本角标、厚重底栏。

## 1. 信息架构与视觉层次

- 第一层：全屏 Three.js 建筑（最主要）。
- 第二层：左上角轻盈的球场名称 + 一行地点信息，或小型半透明信息块。无 Logo、品牌横幅、版本角标；正文尽量少。
- 第三层：底部居中浮动 Dock；其余配置收进 Popover/侧边栏，默认关闭。
- 第四层：“关于球场”可由小号 ⓘ 信息按钮开启；内容中允许注明真实改建年份、简要资料来源，但不要展示 `V1/V2`、`精修版` 等工作流状态。
- 开发/QA 相关状态如 `V1`、`V2`、`Prototype`、FPS、`scene ready` 只在代码和报告中存在。测试可以读取隐藏 `aria-live` 状态，不能在可见页面暴露。

## 2. 设计 Token 与布局

- 字体：系统 UI 字体栈 `-apple-system, BlinkMacSystemFont, "SF Pro Display", "Segoe UI", sans-serif`；若系统没有 SF Pro 自动降级；不包含字体文件。
- 主标题：16–22px，font-weight 600，line-height 1.2，letter-spacing 约 -0.02em；辅助文字 11–13px，低对比但可读。
- 控件文字：12–13px，font-weight 500；按钮高度目标 44–48px，触摸目标不小于 44px。
- Dock：自适应内容宽度，桌面尽量少于 720px；不拉满整个屏幕宽度。`border-radius: 20–24px`、半透明表面 `rgba(16,22,30,.58)`、`backdrop-filter: blur(22px) saturate(140%)`、1px 极浅内外边线和柔和阴影。
- 颜色：黑曜/石墨/深海灰 + 白色文字；最多一种低饱和冷白/蓝灰强调色。避免大量金黄、宝蓝描边、彩虹高光、霓虹泛光、硬阴影。
- 选中态：半透明柔和填充；按钮可 hover/focus，默认不铺满边框。使用线性 SVG 图标（统一 1.7–1.9 strokeWidth）和简短可读中文标签。
- 间距：4/8/12/16/24/32px 体系，整体多留白，确保自然层次。

## 3. 默认屏幕排布

- 左上角：`CAMP NOU` 或 `Camp Nou` + `Barcelona, Catalunya`（已验证时）；绝不出现 `S/A`、`STADIUM ATLAS`、`建筑图鉴 001`、`V2`、`精修版`。
- 右上角：至多一个小号信息/设置按钮，不要加无意义装饰图标。
- 底部：视角切换组 `[全景] [草坪] [看台] [重置]`，轻分割线，环境组 `[日间] [夜间]`。专属按钮确有功能时可以进入二级菜单。
- 手机：Dock 可横向滚动/折叠，必须可操作；可以隐藏一部分非关键的文字标签，但必须保留 `aria-label`。

## 4. 禁止事项（硬性质量门槛）

1. 页头任何形式的 V1/V2/Pro/精修版、进度标签和开发测试状态。
2. S/A、S-A、无用户明确要求的品牌 Logo，或占据大量空间的球场名称。
3. 厚重的全宽底栏、全按钮描边、序号导航和大片实色底板。
4. 过度模糊造成文字不可读、低对比度按钮、过多功能影响探索。
5. 纯视觉假按钮、状态与 aria-pressed 不匹配、移动端溢出。
6. 为“像苹果”直接复制 Apple 商标、专有图片、界面资产。

## 5. 可测试验收

- `document.body` 可见文本不出现：`V1`、`V2`、`精修版`、`S/A`、`STADIUM ATLAS`、`Prototype`、`Starter`（注意文档/开发控制台不属于可见网页）。
- 1280×800 和 390×844 预览截图中底栏不会遮挡球场关键结构，也不发生明显横向溢出。
- `全景`、`球场内`、`看台`、`日间`、`夜间` 等按钮有真实事件，并能更新活跃/选中状态。
- Dock 默认能看到的只是当前高频动作，不出现 01/02/03 的序号。
- 保留 `prefers-reduced-motion` 与键盘焦点表现，满足基础可访问性。

## 6. 用户反馈优先级

用户明确要求去掉装饰性标签或更换设计风格时，立即调整该项目的 UI 以及未来默认模板；仅更新插件本身不会自动修改先前已生成的项目，需对那个项目源码单独执行修复。
